# FieLanzen Offline 0.2.1

**Reguläres Wartungsrelease · 26. November 2026**  
**Regular maintenance release · 26 November 2026**

## Änderungen (Deutsch)

### Korrektur: Serverbuchungen lassen sich wieder löschen

Version **0.2.1** behebt einen Fehler beim Löschen von Buchungen im Dashboard-Servermodus. Betroffen waren sowohl selbst angelegte Testbuchungen als auch Korrekturbuchungen, die durch einen **Kontostandsabgleich bzw. eine Saldoanpassung** entstanden sind. Die vorhandene Android-Version schickte bei einem `DELETE`-Aufruf teilweise `null` statt eines JSON-Objekts, obwohl das Finanzdashboard für diesen Endpunkt ein gültiges JSON-Objekt erwartet. Das führte zu **HTTP 400** und einem sicherheitshalber gespeicherten **offenen Löschauftrag**.

- Für `DELETE /api/mobile/v1/bookings/{id}` wird nun ein leeres JSON-Objekt (`{}`) gesendet, wenn bisher keine Nutzdaten vorhanden waren.
- Auch ältere, verschlüsselt gespeicherte Löschaufträge mit `data: null` werden beim expliziten erneuten Senden korrekt übertragen. **Ziel, UUID (Idempotency-Key), Revision (If-Match) und gespeicherter Auftrag bleiben unverändert.**
- Regelarchivierungen behalten weiterhin das erforderliche Feld `confirm_title` und werden nicht verändert.
- Bei API-Fehlern zeigt die App nach Möglichkeit die konkrete Serverbegründung an. Bei offenen Schreibaufträgen wird außerdem der Zielpfad angezeigt.
- Vor der Wiederholung eines offenen `DELETE`-Auftrags muss der Datensatz auf dem Server kontrolliert und die Wiederholung ausdrücklich bestätigt werden. Es gibt **keine automatischen Wiederholungen** mit neuer UUID.
- Kontostandsabgleich, lokale SQLite-Daten, bestehende Buchungen, API-Berechtigungen und das Sicherungsformat bleiben unverändert.

### Hinweis zu bereits offenen Löschaufträgen

Wer nach einer fehlgeschlagenen Löschung einen offenen Server-Schreibauftrag sieht, sollte **zuerst in der Weboberfläche prüfen, ob die betreffende Buchung noch vorhanden ist**. Bei bereits erfolgter Löschung darf der Auftrag nicht einfach erneut ausgeführt werden. Nach eindeutiger Prüfung kann er über **„Nach Kontrolle freigeben“** verworfen werden. Bei weiterhin vorhandener Buchung ermöglicht die korrigierte App einen ausdrücklich bestätigten Wiederholungsversuch mit derselben UUID. Ein Eintrag `/api/mobile/v1/recurring/...` betrifft eine Regel statt einer einzelnen Buchung.

### Installation und Veröffentlichung

- Regulär signierte APK; APK-Version **0.2.1**, Android-`versionCode` **20100** statt **20000**.
- Die Paketkennung bleibt `de.fielanzen.offline`. Dieselbe Release-Signatur ermöglicht eine Installation als Update über **0.2.0**, ohne die App vorher zu deinstallieren.
- Eine SHA256-Prüfsumme wird neben der APK veröffentlicht. Quelltext und GNU-GPL-v2-only-Lizenz stehen mit dem Release-Tag bereit.
- Die automatisierten Tests prüfen den Löschaufruf, gespeicherte Altaufträge, Regelarchivierungen und die neue Fehlermeldung. Ein vollständiger Gerätetest am produktiven Server ist weiterhin erforderlich.

## Changes (English)

### Fixed deleting Dashboard server bookings

**FieLanzen 0.2.1** corrects an HTTP 400 error when deleting server bookings, including test transactions and adjustment bookings created by a **balance reconciliation (Saldoanpassung)**. The Android client previously sent `null` to an endpoint requiring a JSON object.

- Booking DELETE requests now transmit an empty JSON object (`{}`) when no other request body exists.
- Stored requests originating from 0.2.0 are normalized **on the wire only**, preserving their original **UUID**, If-Match revision, server target and encrypted pending record.
- Recurring-rule archive requests still carry `confirm_title`.
- Detailed safe API error messages and the pending endpoint path are shown where available.
- Repeating a pending deletion requires explicit server-state verification and confirmation. There are no silent retries or new UUIDs for unknown outcomes.
- The local SQLite database, account balance reconciliation, backups, permissions and server APIs are unchanged.

### Safe upgrade

Before retrying a pending deletion, verify in the Dashboard web UI whether the target booking still exists. Do not retry an already-completed deletion. Once the outcome is confirmed, the pending operation may be cleared explicitly in the app.

The stable release retains package ID `de.fielanzen.offline` and the established signing certificate, raising Android `versionCode` from **20000** to **20100**. Install it directly over 0.2.0; do not uninstall and risk local finance data. The signed APK and **SHA256** checksum are released together. Automated tests and signing verification do not replace a real-device test.
